## Fixed in this audit (on `audit/2026-11-10`)

### Bugs

**S1. An empty or badly encoded page failed both sources and showed a 500.** (`25f6b9d`) An empty 200 response raised lxml's `XMLSyntaxError` (`recover=True` still refuses an empty document), and a single non-UTF-8 byte in the Chant Stand page raised `UnicodeDecodeError`. Neither is a `ScrapeError` or an `httpx` error, so `sunday.fetch_readings` re-raised it. The volunteer got "Something went wrong", nothing was saved to `state/failed-downloads/`, and the *other* source's good readings were thrown away, which is the opposite of the documented design. Now `SourceArchive.fetch_xml` raises a `ScrapeError` naming the URL, and `fetch_html` decodes with `errors="replace"`. Tests: `test_an_empty_page_fails_only_its_own_source`, `test_a_stray_byte_in_the_chant_stand_page_is_read_past` (both fail without the fix).

**S3. Changed Chant Stand markup failed both sources too.** (`b116be2`) Same failure as S1, through another route: if the Alleluia verses lose their `data-key*="alleluia"` attribute (exactly the kind of change goarch.org will make over ten years), `css_first()` returns `None` and `.text()` raises `AttributeError`. `goarch_xml_feed.fetch_and_process` already turned `AttributeError`/`IndexError`/`ValueError` into `ScrapeError`; `digital_chant_stand.scrape` now does the same. Test: `test_changed_chant_stand_markup_fails_only_its_own_source`. (L1 is the general version of S1 and S3.)

**S4. A day without an icon lost its readings.** (`0cef822`) The icon is deliberately never printed, and a failed icon *download* only warns, but `process_daily_feed_page` read `<icon>` with `xpath_text`, which raises. A feed without the element failed the whole Online Chapel source: no title, epistle or gospel. It's now optional end to end. Test: `test_a_day_without_an_icon_keeps_its_readings`.

**S5. The prokeimenon's unprinted mode could fail the readings.** (`cb52778`) Same pattern: `EpistlePageData.mode` is never used, but `int(xpath_text(... "prokmode"))` raised on a missing or non-numeric mode. Every archived value is a digit, so this hasn't happened yet; it's now `None` instead.

**S6. A hand-edited `manual.yaml` that `manual.read` accepts could stop the bulletin.** (`0f36f9d`) Typst read the fields directly. Rendering in a scratch copy: `page: 225` (the most natural hand edit) gave "expected content, found integer". A hymn without a `mode` key, a service without a `priest`, a file without one of its two lists, or an empty file each gave "dictionary does not contain key …". The Sunday page shows these hymns fine, then step 3 says "a problem in the program". `inputs.typ` now has `text_field(entry, key)`, which returns `""` for a missing field, and `bulletin.typ`/`bulletin_back.typ` use it. **The snapshot pictures are pixel-identical** (their hashes pass). Test: `test_a_hand_edited_manual_file_renders` (three cases).

**S7. "Apolytikion for the Temple, Mode 4" was read as mode 8.** (`6361346`) `commemorations.mode_number` treated any `"pl"` as plagal ("tem**pl**e"), and `chant_stand_mode` read "First" in a title like "Kontakion for the First Sunday of Lent" as mode 1. Today's Chant Stand titles happen to avoid both, but the titles change through the church year, and the mode goes into the "Add to Hymns of the Day" button. Now "pl" must start a word, and a title is read for a mode only when it says "Mode" or "Grave". Tests: a new `mode_number` case and `test_chant_stand_mode`.

**S8. A line break pasted into the prokeimenon or its verse printed as a hard break.** (`b88db03`) Both are textareas, and unlike the readings their text wasn't collapsed. Typst prints a newline inside a string as a line break (checked with a render), and the text sizing doesn't count the extra line. Now collapsed on save (`web.one_line`). Extended `test_readings_can_be_typed_in_by_hand`.

**S9. Preview pictures could 404 while a Sunday was re-rendered.** (`1761542`) `render.render` deleted every `preview-N.png` before writing the new ones, and `/preview-N.png` is served without `WORK_LOCK`, so a picture requested in between (a second tab, or a settings page rendering the same Sunday) broke. Now each picture is replaced atomically and only pages that no longer exist are removed. Test: `test_pictures_of_pages_no_longer_there_are_removed`.

**S10. The front page printed "November 08, 2026".** (`0f99e24`) goarch.org zero-pads days below 10; `sunday.long_date` (used for hand-typed readings) doesn't. The leading zero is now dropped when the feed is read. This affects new downloads only: existing Sunday folders keep what they have until downloaded again or edited. December 6 is the next Sunday this would have hit. Test: `test_formatted_date_is_not_zero_padded`.

### Security

**S11. Without a password, a web page could reach the app through DNS rebinding.** (`f4b6b0f`) Listening on 127.0.0.1 doesn't stop a page whose own hostname has been re-pointed at 127.0.0.1: its requests are same-origin, so `Sec-Fetch-Site` lets its POSTs through (reproduced: the undo form answered 303) and it could read `/settings/backup.zip`. Without a password, a request whose `Host` isn't localhost, 127.0.0.1 or ::1 now gets a 403. Nothing changes with a password (the deployed setup). AGENTS.md "Safety" updated. Test: `test_without_a_password_only_this_computer_is_served`.

### Tests, docs and tidying

**S2. Six snapshot tests failed.** (`9a774f3`) `archive/` had 2026-10-11 to 2026-11-15 committed without snapshots. Generated with `UPDATE_SNAPSHOTS=1` after checking the scraped data (titles, books, sizes, hymn counts: the Lukan Jump and St. Luke's feast on 10-18 are correct) and looking at both booklet sides of 10-25 and 11-08. The three existing Sundays' snapshots and picture hashes came out unchanged. `test_commemorations.py` already covered all nine.

**S12. Three copies of the atomic write.** (`1d560b4`) `yaml_io.write_yaml`, `render.write_atomic` and `parish.write_if_changed` each wrote to `.partial` and renamed. Now one `yaml_io.write_atomic`.

**S13. The handover sheet named a button that doesn't exist.** (`9e7a797`) Step 4 said **Save**; the button is **Save hymns and services**. And "3 pages instead of 2" said to print anyway, though the Sunday page now points to a smaller text size under **Edit the readings** (added the same day the sheet was written). This sheet is what a volunteer follows word for word.

**S14. Task 002's known state was out of date.** (`f29b888`) It said the dismissal hymns miss the Resurrectional Apolytikion for 2026-09-27; that was fixed when `group_by_sections` became a list, and a test checks every archived Sunday. Added a dated note.

## Noted, not changed

**N1. A download holds `WORK_LOCK` for up to a minute.** `web.fetch` runs the whole download under the lock, so any other page that renders (a Sunday page, a settings page's preview) waits for it. With one volunteer this never shows. If it ever does, split `fetch_readings` into the network part (no lock) and the writing part (locked).

**N2. Generated files grow about 40 MB a year.** Each Sunday keeps two PDFs and two preview PNGs (~800 KB, measured), all regenerable. Over ten years that's ~400 MB on the Railway volume. If the volume is small, delete the PDFs and pictures of Sundays more than a few months old (they come back when opened); `backup.GENERATED` already lists them.

**N3. Sundays from before the sizing fields don't render.** A `feed.yaml` without `text_size_factor` fails in Typst (`none / 100`) with "a problem in the program". The owner sized the two such Sundays (task 005). If more old folders are ever restored, run `uv run text_sizing.py <date>` on them, or have `render.ensure_rendered` size a Sunday that has no sizing yet.

**N4. Typst and Python merge the settings slightly differently.** `parish.load` falls back to the default for a value of the wrong type, while `inputs.typ` overlays whatever is in `state/settings/parish.yaml`. Only a hand edit of that file can produce a wrong type (`parish.save` never does), so this is a note for whoever edits it by hand.

**N5. Service dates are carried over only as mm/dd/yyyy.** `manual.parse_service_date` is strict, so "11/14/26" is printed as typed but silently not carried to next week's template. The form's hint asks for the four-digit year, and the template is visible before saving.

**N6. Carry-over happens when the readings are downloaded.** `fetch_readings` writes the `manual.yaml` template then, so if last week's upcoming services are changed after next week was downloaded, next week doesn't pick up the change. The services are visible in the form before saving.

**N7. Login attempts are slowed but not limited.** A failed login waits a second, per thread (waitress runs 4). The password's length is the real defence: worth a line on the handover sheet that it should be a long passphrase.

**N8. With `liturgy_day: sunday`, "Next Sunday" moves on during Sunday's Liturgy.** `sunday.next_sunday` on a Sunday is the following week. That's right for this mission (Saturday Liturgy) and only matters if it ever gets a resident priest.

**N9. Unused code and files, already tracked.** The DCS readings and prokeimenon helpers (`get_scripture_reading_data`, `get_reading`, `get_prokeimenon`, which no longer matches the markup) and `EpistlePageData.mode` are task 002's decision. `assets/church.webp` is listed in task 005 "Small cleanups".

**N10. The suggestion lists read the latest 52 folders by name.** `manual.recent_details` and `commemorations.add_past_titles` sort `state/sundays/` and take 52, which includes Sundays prepared ahead and any folder that isn't a date. Harmless; `sunday.saved_dates()` is the stricter listing if it ever matters.

**N11. Lint is clean.** `ruff check --select F,E9,B,UP,SIM,PERF,RUF` finds nothing in the app code except `zip()` without `strict=` over the form's columns in `web.py`, which is right there: `strict=True` would turn a hand-crafted POST into a 500.

### Checked and found sound

- **XML safety:** the parsers use `resolve_entities=False, no_network=True`, which is also the mitigation for the lxml advisory in L3.
- **Paths:** the logo path, static files and preview numbers can't leave their folders; uploaded images are named by hash and checked by their first bytes and a trial compile.
- **Escaping:** Jinja autoescaping everywhere, `tojson` (which escapes `'`) for the data attributes, a strict CSP with no inline script, and Typst prints YAML strings literally.
- **Sessions:** HMAC-signed expiry, `compare_digest`, HttpOnly + SameSite=Lax + Secure over HTTPS; `safe_next` only allows local paths.
- **Time zone:** `TZ=America/Phoenix` works in `python:3.13-slim-trixie` (checked in the image: MST, −7h), so "next Sunday" turns over at local midnight.
- **Secrets:** `.env.local`/`.env.prod` are untracked and absent from the git history.
- **The label helpers** (`priest_label`, `page_label`, `expand_abbreviations`, `typographic`) gave the right answer on every edge case tried ("Frank", "Page 4", "pp. 12", "Sunflower", "'90s", nested quotes).
